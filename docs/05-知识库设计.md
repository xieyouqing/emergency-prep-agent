# 05-知识库设计（设计稿，未实现）

> 状态：2026-11-04 定稿设计，**代码未写**。用途：日常问答模块（`src/daily/` + 后端）的知识库规范。
> 前提：日常问答面向**平时**场景，可依赖网络；断网按基线 §2 转渠道，不做离线答案。

## 1. 收什么（范围）

只收三类，不做通用百科：

1. 14 项条目的名称 / 用途 / 判据 / howto
2. 权威动作指南（应急管理部、红十字会、消防救援局）的**原文段落**
3. 高频日常问题（停电、停水、燃气味、伤口、被困、地震躲避…），每条必须挂到第 1 或第 2 类的某一段

**不收**：用药、剂量、止血带时长、任何医疗判断（直接转渠道，见基线 §5）。

## 2. 切片规范

- 一段 = **一个动作或一条判据**，50–150 字
- 粗切（整篇）检索出来无法引用；细切（一句）丢上下文
- 每段元数据：

```
id            片段唯一标识
text          原文片段
source_name   来源名称（如「安徽省家庭应急物资储备建议清单（基础版）」）
source_url    链接
fetch_date    抓取日
level         official | consensus | cross-checked   ← inferred 不入库
scope         适用灾种 ['fire'] / ['flood'] / []
item_id       对应条目 id（可空）
version       知识库版本
```

## 3. 入库门槛（控制来源的唯一手段）

- **只收 `official` / `consensus` / `cross-checked` 三级**
- **`inferred` 一律不入库**：10 条推断判据只在自查界面带「仅供参考」显示，不喂给检索
- 同一主题多源冲突 → 全部入库并标 `conflict=true`，回答时并列，不替用户选

## 4. 检索策略

1. 按 `scope` 过滤（灾种不匹配的先排除）
2. 全文/向量相似度取 top 3–5
3. 低于阈值 → 判「查不到」→ 转渠道（不给「大概」答案）
4. **不靠模型先验补答案**：检索结果为空就是空

技术选型：**20–50 段时先 SQLite FTS5**，可解释、依赖少；检索层做成可替换接口，片段涨到 200+ 再换向量库。

## 5. 回答格式

- 正文 ≤ 3 句
- **必带来源列表**：名称 / 链接 / 获取日 / 等级
- 凑不出来源 → 不答，转渠道
- 超过 90 天的来源标「可能已更新」

## 6. 评测集（最容易被省掉，必须做）

- 20 条问题 × 期望来源片段
- 每次改知识库跑一遍
- 门槛：**命中率 ≥ 80%** 且 **「无来源回答数 = 0」**

## 6.1 生成阶段（G）—— 下个版本，不在本期

**现状**：只做检索（R），返回原文片段，不做模型生成。理由：17 段单跳问题，原文即答案；生成会引入改写风险，溯源变难。

**上 G 的触发条件**（任一成立再做）：
- 问题需要跨多段综合（如「住高楼有老人，火灾该备什么」）
- 片段过长需要摘要
- 检索命中但原文读不懂

**上 G 时必须配的约束**：
1. prompt 强制「只依据给定片段回答，每句标 `[S1]` 引用」
2. 后置校验：每句必须能映射到某片段关键词，映射不上就整段丢
3. 校验不过 → 降级为直接返回原文（当前行为）
4. 前置条件：先有 20 条评测集，否则无法证明生成优于原文

## 6.2 返回文本三层（V1.1，2026-11-05 定方向）

**问题**：现在是原文片段直接当答案——问「水要备多少」返回「饮用水属于什么」，答非所问，且像说明书。

**结构**（每段知识库新增两个字段）：

```
answer  一句人话直接回答（我方改写，如「每人每天 1 升，备足 3 天」）
quote   支撑 answer 的原文片段（现有 text）
sources 出处（名称 / 链接 / 获取日 / 等级）
```

**规则**
- 前端展示：`answer` 在上，`quote` 与 `sources` 折叠在下面
- `answer` 是我方改写，**必须与 `quote` 语义一致**；校验不一致的段落降级为只显示原文
- `answer` 不引入模型生成（生成阶段的约束见 §6.1）
