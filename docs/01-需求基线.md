> 状态：训练产出。**v1.2（2026-11-04）**：补数据边界与三层降级、日常问答来源协议，理由见 §11。

## 1. 目标与用户

**要解决的问题**：公众应急准备不足，知道但没做。

**证据**
- 38.7% 的公众防震避险能力不足（[中国地震局调查](https://www.cea.gov.cn/cea/xwzx/zyzt/5841209/5841222/5843000/index.html)）
- 四维度短板：避险知识技能相对较好；风险与科学认知、防灾意识与应急准备、信息渠道多元化不足
- 能力与受教育程度正相关；学生组 21.9% 最高（有组织演练的群体能力更高）

**角色**
- 受益者：老人与受教育程度较低者，日常场景
- 使用者：老人本人，或子女 / 社区网格员代操作

**非目标用户**：救援队、专业人士；无法独立操作智能手机者（由子女/社区代操作路径覆盖，理由：交互保底能力不足）

## 2. 形态与产物（终点 = 配齐）

**形态**：单入口 Agent。打开即进入自查流程第一步，按钮三选一（有 / 没有 / 不确定），自查流程内不需打字。
**意图识别**：只用于流程中的偏离分流，不用于决定入口。

**载体与数据**（v1.1）
- Web 单页应用，可「添加到主屏幕」；不做注册，数据存本机（localStorage / IndexedDB）。
- 换机、清缓存即丢，不迁移 → 记入 §8。

**触发时机**（v1.1，一律「打开时」判定，不依赖推送）
- 无完成记录 → 首次进入自查流程。
- 有记录且距上次完成 ≥ 90 天，或发生关键事件（买过 / 换过 / 过期 / 搬家 / 家庭结构变化）→ 顶部不阻断条提示。
- 首次弹窗被关闭 → 距上次提示 ≥ 3 天才再弹一次。
- 首次弹窗常驻「我现在有急事」，直达紧急分支；它不属于自查流程。
- 三态：完成 / 稍后（24 小时后再提）/ 别再问（可撤销）。
- 每轮自查末尾固定一屏「顺手看一眼」（3–5 项 + 判据），维护检查并入自查，不另设节律。
- 「完成」＝ 走完一轮自查（每项都答过），**不等于 14 项配齐**；配齐程度另记。

**转发边界**（v1.1）
- 调起系统短信并预填内容，由用户按下发送；不自动发送，不接微信个人号。子女号码存本机。

**误触与撤回**（v1.1）
- 动作执行后 5 秒内浮出「撤销」，之后收进「上一步」。
- 紧急号码走「调起系统拨号盘并预填」路径，不直接拨号；系统拨号器本身即防误触，不算二次确认。

**三层降级**（v1.2）
- **紧急**：独立页，120/119 为常量，零数据依赖；入口每屏常驻，不受网络、数据加载、缓存影响。
- **自查**：离线优先，14 项 + 判据内置；在线仅用于更新数据版本（后台静默、整包替换、旧版可回退）。
- **日常**：在线优先；查不到、来源不在清单、或依赖不可用时，降级为转渠道（号码 / 网址），不是「答不上来」。

**产物（选 B：配齐/有人接手）**
1. 分层后的"本家庭适用清单"
2. **下一步只有一件**（今天就能做的那件）
3. 一键生成可转发的代办消息（发给子女 / 社区）

**"不确定"分支**（三选一，必须落地，不许死路）
- 10 秒可验证 → 给验证方法，确定后继续下一项
- 无法验证（独居/行动不便）→ 走"找人帮"路径
- 确认没有 → 进"待采购"，按优先级排序

## 3. 条目与裁剪规则

**条目池**：安徽省《家庭应急物资储备建议清单》基础版 4 大类 14 项（省应急厅、卫健委、商务厅、消防救援局，皖应急函〔2024〕218号，2024-07-26；原文与抓取记录见 `04-数据来源.md`）

**裁剪三维**
- 按灾种：火灾（呼吸面罩、灭火器/防火毯）／洪水（救生衣、救生圈）／全灾种
- 按家庭结构：有老人 → 常用药 + 联系人卡；有婴儿 → 奶粉等
- 按预算空间：帐篷、逃生绳属高层或地震多发才需要

**必配最低集**（全灾种 + 低价 + 高频）：手电（可手摇充电）、救生哨、饮用水与压缩饼干、毛巾/纸巾、创可贴 + 纱布绷带 + 碘伏棉棒

## 4. 准确性（C）

- **条目来源**：采用省级官方清单，标注来源与版本日期；具体件数按家庭裁剪，但类别须可回指清单
- **不可自检项**必须给可操作判据；给不出判据的项不入清单
- **动作库来源协议**：≥2 个权威来源（应急管理部、红十字会、消防救援局）表述一致的动作才入库；有分歧的一律转渠道
- **时效维护**：不记单件到期日（录入成本高、错录比不录更糟）；改为每轮自查末尾固定一屏「顺手看一眼」，列 3–5 项高失效风险条目，每项给一句 10 秒判据。维护检查并入自查，不另设提醒。

**日常问答来源协议**（v1.2）
- 允许来源：应急管理部、红十字会、消防救援局、当地应急管理部门官网与官方号；清单外的来源不直接采信。
- 每条答案带来源名称、链接、获取日期；无来源则不答，转渠道。
- 与内置自查数据冲突时，取更保守的一版并标明冲突，不默认其中一方。
- 用药 / 药量 / 止血带时长不给判断，直接转渠道（见 §5）。
- 超过 90 天的答案标「可能已更新」；有保质期的条目以用户手里的包装为准。

## 5. 超范围行为（E）

**入口**：疑似紧急 → 一律按紧急处理，不二次确认
触发：求救命类语句 / 出血不止 / 倒下 / "现在""马上" / 第一人称遇险

**紧急**
- 一步零分歧动作 ＋ 同时给 120、119（预存号码）
- 不给多轮确认、不给有分歧的指令（用药、药量、止血带时长）
- 原则：紧急时说得越少越安全

**日常**
- 检索得到 → 答 + 来源
- 检索不到 → 转渠道（号码/网址）
- 渠道不可用（网络波动常见）→ 30 分钟后重试；白天、能走动、知道方向时可前往就近应急避难场所

**兜底链**：动作 → 电话 → 现场求助（呼救、邻居、社区）

## 6. 验收标准（可测）

> v1.1 改写：每条按「条件 / 操作 / 预期」写；条件不满足时不判。

1. **清单可生成且每项可判**
   - 条件：已输入家庭结构（有无老人 / 婴儿）、灾种（火灾 / 洪水 / 其他）、居住形态（高层 / 低层）
   - 操作：走完一轮自查
   - 预期：清单只含与输入匹配的条目；每条附一句 10 秒判据，或标注「转渠道」；不出现既无判据也不转渠道的条目；每条可回指省级清单名称与版本
2. **8 分钟拿到下一步**
   - 条件：5 名未使用过本产品的目标用户（≥60 岁或受教育程度较低）、常用手机、网络正常、应用已在前台
   - 操作：用户自行操作，全程不给提示、不代点
   - 预期：从应用在前台到出现「下一步一件事」≤ X 分钟（X 先测 5 人再定，不预先写死）；全程无需文本输入；记录卡住的屏与时长
3. **交互约束**
   - 条件：任一屏，含每轮末尾的「顺手看一眼」屏
   - 操作：不滚动
   - 预期：主操作按钮 ≤ 3 且全部可见；辅助入口最多 2 个（「我现在有急事」常驻 + 「撤销」短时出现），不计入主操作；自查流程内不出现文本输入框
4. **「不确定」无死路**
   - 条件：任取一个「不确定」项
   - 操作：按三选一逐个走一遍
   - 预期：2 步内到达验证方法 / 找人帮 / 待采购之一；不出现「无路可走」，也不出现「回到同一屏循环」；三条分支各至少能退回上一步
5. **代办消息可转发**
   - 条件：有待采购或需他人代办的条目
   - 操作：点「转发」
   - 预期：调起系统短信，收件人与内容已预填，用户按下发送即完成；不出现「复制后去微信发送」的步骤

## 7. 非目标

- 不做视觉识别判定（拍照判断佩戴/包扎）
- 不做语音陪练（语音属技术选型，后续评估）
- 不做在线演练评估
- 不做代购、上门配送、社区系统对接
- 不服务无法独立操作智能手机者
- 不做独立知识库/科普模块（知识仅以清单第 14 项形态出现）

## 8. 已知缺口（只记录，本期不解决）

- 外部数据依赖与维护责任：14 项省级清单、动作库、离线号码
- 清单与号码的更新、版本管理
- 合规：能力边界声明与免责声明的展示位置
- 度量：`不确定` 占比、自查完成率、单件完成率（留计数器即可）
- 跨设备数据迁移：Web 本地存储，换机 / 清缓存即丢；本期不做迁移（后续可选 6 位迁移码）
- 数据来源：清单条目为预置文本；运行时只存「上次完成时间」与「家庭结构」，不存单件到期日（见 §4）

## 9. 三个歧义（完成定义）

| 歧义 | 答案 |
|---|---|
| 用户是谁 | 老人 + 受教育程度较低者；排除救援队、专业人士、无法操作手机者 |
| 准确怎么判 | 来源一致（≥2 权威）＋ 可操作判据；不依赖医学判断 |
| 答不上来怎么办 | 分紧急/日常；动作 → 电话 → 现场求助 三层兜底 |

## 11. 变更记录

- **v1.1（2026-11-03）** 补四类设计决策：
  - **载体**：小程序需注册与类目审核，11/11 前不可行 → 改 Web 单页；代价是本地存储易丢、Web Push 不可用，均记入 §8。
  - **触发**：网页形态下推送不可靠 → 一律「打开时判定」；首轮 90 天 + 事件触发，避免到点骚扰；区分「完成」与「配齐」，否则低配家庭永远出不了循环。
  - **转发**：微信无个人号接口、iOS 不支持预填收件人 → 只做短信预填、由用户发送。
  - **误触**：撤回是事后按钮、二次确认是事前拦截，二者不冲突 → 紧急流程同样给撤回；拨号走系统拨号盘，不直接拨打。
  - **维护节律**：不记单件到期日；检查并入每轮自查末尾一屏「顺手看一眼」，全产品只保留一个节律、一个入口。
  - **验收**：五条改为「条件 / 操作 / 预期」；计时起点＝应用已在前台；不打字范围限定自查流程；「一屏」改为「不滚动即可看到全部可点元素」；8 分钟的 X 先测 5 人再定。
  - **计数口径**：实现撤销与紧急入口时发现「每屏可点元素 ≤3」装不下 → 改为主操作 ≤3，辅助入口 ≤2（急事常驻、撤销短时），理由：老人手机上这两条是不同的通道，压缩成一个反而有害。

- **v1.2（2026-11-04）** 补边界：
  - **三层降级**：紧急（常量、零数据依赖）/ 自查（离线优先、数据内置）/ 日常（在线优先、失败转渠道）。理由：越靠近救命，越不依赖外部条件；断网是灾害现场的常态。
  - **来源协议**：允许来源清单 + 必带来源与获取日 + 冲突取保守 + 用药类不判断 + 90 天时效标注。理由：在线检索不给规则就等于模型自由发挥。
  - **注意**：紧急路径与自查路径分开写，不共用降级规则——两者的失败方式不同。
